"La 4a SSD" la eliges tu: las 4 son iguales. 3 al RAID, la que sobra

3.1 Tabla GPT nueva en los 5 discos (Figura 8):
  echo -e "g\nw\n" | sudo fdisk /dev/sdb
  echo -e "g\nw\n" | sudo fdisk /dev/sdc
  echo -e "g\nw\n" | sudo fdisk /dev/sdd
  echo -e "g\nw\n" | sudo fdisk /dev/sde
  echo -e "g\nw\n" | sudo fdisk /dev/sdf
    echo -e  -> \n = Enter; la tuberia | se lo pasa a fdisk
    g        -> tabla de particiones GPT vacia
    w        -> escribir y salir (sin w no se guarda)

3.2 LAS DOS SECUENCIAS DE FDISK
  Formula: g n 1 Enter, luego TAMANO o Enter, luego t TIPO w

  A) SSD del RAID (las 3):        B) HDD y 4a SSD:
     sudo fdisk /dev/sdX             sudo fdisk /dev/sdX
     g       tabla GPT               g
     n       particion nueva         n
     1       numero 1                1
     Enter   primer sector 2048      Enter
     +100G   ULTIMO SECTOR = TAMANO  Enter  HASTA EL FINAL (disco entero)
     t       cambiar tipo            t
     raid    Linux RAID (n. 43)      linux  Linux filesystem (n. 20)
     w       guardar                 w
  Si pregunta "eliminar la firma?" -> S / Y

  Las dos preguntas tras "n" y "1":
    Primer sector (..., valor predeterminado 2048):        -> Enter
    Ultimo sector, +/-sectores o +/-tamano{K,M,G,T,P}:     -> +100G o Enter

  Tamano: el enunciado dice "200M" y "100 GB". Usa +100G: con 200M el
  RAID tendria ~400 MB y NO cabe el fichero de 1 GiB del benchmark.

  Si al poner el tipo pulsas L o Enter sale una lista larga con ":"
  abajo -> pulsa q para salir y escribe raid o linux.

  Una linea (si no hay pregunta de firma):
    echo -e "g\nn\n1\n\n+100G\nt\nraid\nw\n" | sudo fdisk /dev/sdb
    echo -e "g\nn\n1\n\n\nt\nlinux\nw\n"     | sudo fdisk /dev/sdf

3.3 Comprobar (Figuras 9-12):

    --create        crea matriz nueva   --verbose  muestra detalles
    /dev/md0        dispositivo RAID    --level=5  (NO --level5= como en P2)
    --raid-devices=3 n. de miembros, seguido de las 3 PARTICIONES
  Preguntas: "write-intent bitmap? [y/N]" -> y (resincroniza solo lo
             cambiado; "Consistency Policy: bitmap")
             "Continue creating array?" -> y
  Termina con: mdadm: array /dev/md0 started.
  OJO: SIN barra al final (/dev/sdd1/ -> "Not a directory").

4.3 Formatear el RAID y ver detalle (Figura 15):
  sudo mkfs.ext4 -F /dev/md0
  cat /proc/mdstat
  sudo mdadm --detail /dev/md0

  Como saber si el RAID esta creado:
   - cat /proc/mdstat: "md0 : active raid5 sdd1[3] sdc1[1] sdb1[0]"
       y "[3/3] [UUU]" (U = sano, _ = caido). Si pone resync = x %,
       esta calculando paridad (normal).
   - lsblk: md0 tipo raid5 debajo de cada miembro
   - mdadm --detail: si no existe -> "cannot open /dev/md0"

  Lectura de /proc/mdstat:
    8378368 blocks  -> bloques de 1 KiB: (3-1) x tamano particion
    super 1.2       -> version del superbloque (lo que borra zero-superblock)
    512k chunk      -> trozo por disco (banda de datos = 2 x 512K = 1 MiB)
    algorithm 2     -> left-symmetric (paridad rotando)
    bitmap          -> write-intent bitmap

  mdadm --detail, valores esperados:
    Raid Level     raid5
    Array Size     ~200 GiB = (3-1) x 100 GiB
    Raid Devices   3 / Total Devices 3
    State          clean (o clean, resyncing)
    Active/Working/Failed/Spare  3/3/0/0
    Layout         left-symmetric
    Chunk Size     512K
    Miembros       active sync

5. FASE 5 - BENCHMARK
---------------------------------------------------------------------
Estrategia (para el Word):
  1. Fichero fijo de 1 GiB y bloque variable (unica variable = bloque).
  2. Antes de cada prueba se vacia la cache: sync; echo 3 > /proc/sys/vm/drop_caches
  3. Escritura con conv=fdatasync: dd no acaba hasta que los datos estan
     en disco -> se mide el disco, no la RAM.
  4. Lectura del mismo fichero a /dev/null.
  5. Tiempo con date antes/despues; Tasa = 1024 MiB / tiempo (MiB/s).

Tabla (count = 1048576 KiB / bs en KiB):
  BlockSize001k_FileSize1Gib.txt   1k    1048576   (enunciado: 1048560 = errata)
  BlockSize002k_FileSize1Gib.txt   2k     524288
  BlockSize004k_FileSize1Gib.txt   4k     262144
  BlockSize008k_FileSize1Gib.txt   8k     131072
  BlockSize016k_FileSize1Gib.txt  16k      65536
  BlockSize032k_FileSize1Gib.txt  32k      32768
  BlockSize064k_FileSize1Gib.txt  64k      16384
  BlockSize128k_FileSize1Gib.txt 128k       8192
  BlockSize256k_FileSize1Gib.txt 256k       4096

Orden dd del primer fichero:
  dd if=/dev/zero of=/mnt/HDD/BlockSize001k_FileSize1Gib.txt bs=1k count=1048576 conv=fdatasync
    if=/dev/zero     fuente de ceros
    of=...           fichero en el punto de montaje del disco medido
    bs=1k            tamano de bloque
    count=1048576    n. de bloques (1048576 x 1 KiB = 1 GiB)
    conv=fdatasync   volcar a disco antes de terminar
  Lectura: dd if=/mnt/HDD/BlockSize001k_FileSize1Gib.txt of=/dev/null bs=1k

Por que NO oflag=direct (P3): con 1 GiB y bloques de 1k tardaria ~220 s
en el HDD y ~1000 s en el RAID 5 -> mas de 1 hora en total. Con
conv=fdatasync todo tarda ~10 min. Decision de diseno justificada.

SCRIPT benchmark.sh (Anexo C)
---------------------------------------------------------------------
#!/bin/bash
# benchmark.sh - Primer parcial ICD. Uso: sudo bash benchmark.sh
# Genera escritura.csv y lectura.csv con el formato DISPOSITIVO;BS;Tiempo;Tasa
export LC_ALL=C                         # punto decimal y salida de dd en ingles
declare -A DIR=( [HDD]=/mnt/HDD [SDD]=/mnt/SDD [RAID5]=/mnt/RAID )
BLOQUES="1 2 4 8 16 32 64 128 256"      # tamanos de bloque en KiB
TAM_KIB=1048576                         # 1 GiB = 1048576 KiB

echo "DISPOSITIVO;BS;Tiempo;Tasa" > escritura.csv
echo "DISPOSITIVO;BS;Tiempo;Tasa" > lectura.csv

limpiar() { sync; echo 3 > /proc/sys/vm/drop_caches; }   # vacia la cache de RAM
ahora()   { date +%s.%N; }                                 # segundos con decimales
fila()    { awk -v d=$1 -v b=$2 -v a=$3 -v z=$4 -v m=$5 \
            'BEGIN { t = z - a; printf "%s;%s;%.3f;%.2f\n", d, b, t, m / t }'; }

for dev in HDD SDD RAID5; do
    ruta=${DIR[$dev]}
    mountpoint -q "$ruta" || { echo "ERROR: $ruta no esta montado"; continue; }
    for k in $BLOQUES; do
        f=$ruta/$(printf "BlockSize%03dk_FileSize1Gib.txt" $k)
        count=$(( TAM_KIB / k ))
        # Escritura: crear el fichero de 1 GiB con bloques de k KiB
        limpiar; t0=$(ahora)
        dd if=/dev/zero of=$f bs=${k}k count=$count conv=fdatasync status=none
        t1=$(ahora); fila $dev ${k}k $t0 $t1 $((TAM_KIB/1024)) >> escritura.csv
        # Lectura: leer el mismo fichero con el mismo bloque
        limpiar; t0=$(ahora)
        dd if=$f of=/dev/null bs=${k}k status=none
        t1=$(ahora); fila $dev ${k}k $t0 $t1 $((TAM_KIB/1024)) >> lectura.csv
        echo "$dev  bs=${k}k  hecho"
    done
done
cat escritura.csv; echo; cat lectura.csv
---------------------------------------------------------------------
Explicacion:
  declare -A DIR   diccionario dispositivo -> punto de montaje
  limpiar          sync + drop_caches (por eso se lanza con sudo bash:
                   "sudo echo 3 > ..." falla, la redireccion no es root)
  mountpoint -q    comprueba que esta montado (si no, medirias el sistema)
  printf %03d      001, 002... para que coincida el nombre con la tabla
  fila             Tiempo = t1 - t0 ; Tasa = 1024 MiB / Tiempo

Ejecutar:
  cd ~/examen
  sudo bash benchmark.sh
  ls -lh /mnt/HDD /mnt/SDD /mnt/RAID
  Orden HDD -> SDD -> RAID5: mientras va el HDD el RAID acaba su resync.
  Antes del RAID: cat /proc/mdstat sin "resync".
  Mientras corre, la terminal NO acepta ordenes (es normal). Para ver
  si avanza, abre OTRA terminal: ps aux | grep "[d]d if" ; ls -l /mnt/RAID
  Para pararlo: Ctrl+C.
  Ensayo en casa con discos pequenos: TAM_KIB=262144 (256 MiB).

# graficas.py - Uso: python3 graficas.py  (en la carpeta de los CSV)
import csv
import matplotlib
matplotlib.use("Agg")                     # genera PNG sin abrir ventanas
import matplotlib.pyplot as plt

for op in ["escritura", "lectura"]:
    datos = {}                            # {dispositivo: [(bs, tiempo, tasa), ...]}
    with open(op + ".csv") as fh:
        for f in csv.DictReader(fh, delimiter=";"):
            datos.setdefault(f["DISPOSITIVO"], []).append(
                (f["BS"], float(f["Tiempo"]), float(f["Tasa"])))
    for col, i, uni in [("Tasa", 2, "MiB/s"), ("Tiempo", 1, "s")]:
        plt.figure(figsize=(9, 5))
        for dev, filas in datos.items():
            plt.plot([x[0] for x in filas], [x[i] for x in filas], marker="o", label=dev)
            for x in filas:               # etiqueta con el valor en cada punto
                plt.annotate(f"{x[i]:.0f}", (x[0], x[i]), fontsize=7,
                             textcoords="offset points", xytext=(0, 5), ha="center")
        plt.yscale("log")
        plt.xlabel("Tamaño de bloque (bs)")
        plt.ylabel(f"{col} ({uni})")
        plt.title(f"{col} de {op} de un fichero de 1 GiB")
        plt.grid(True, which="both", alpha=0.3)
        plt.legend()
        plt.savefig(f"{op}_{col.lower()}.png", dpi=150, bbox_inches="tight")
        print("Generada", f"{op}_{col.lower()}.png")

SCRIPT optimo.sh  ->  bash optimo.sh escritura.csv ; bash optimo.sh lectura.csv
---------------------------------------------------------------------
# optimo.sh - menor bloque que alcanza el 95 % de la tasa maxima
awk -F';' 'NR > 1 { d[NR] = $1; b[NR] = $2; t[NR] = $4; if ($4 > m[$1]) m[$1] = $4 }
  END { for (i = 2; i <= NR; i++)
          if (!(d[i] in o) && t[i] >= 0.95 * m[d[i]]) { o[d[i]] = b[i]; v[d[i]] = t[i] }
        for (x in o) printf "%-6s bs optimo = %-5s %8.2f MiB/s (maximo %.2f)\n", x, o[x], v[x], m[x] }' "$1"
---------------------------------------------------------------------
Criterio de bloque optimo: el MENOR bloque que alcanza el 95 % de la
tasa maxima del dispositivo (por encima, la curva es plana).

Que deberias ver:
  - Curvas que suben con el bloque y se aplanan (coste fijo por syscall).
  - Orden: HDD < SDD < RAID5.
  - Meseta (P3): HDD ~36-40 MiB/s, SSD ~490-520, RAID 5 ~900-1200.
  - Con fdatasync la caida con 1k-4k es menor que en la P3; optimo
    entre 16k y 256k.
  - Lectura absurda (3000 MiB/s en HDD) = no se vacio la cache.

Plantilla de conclusiones:
  "El benchmark escribe y lee un fichero de 1 GiB con bloques de 1 a
  256 KiB, vaciando la cache antes de cada prueba. En los tres
  dispositivos la tasa crece con el bloque hasta estabilizarse a partir
  de ___ KiB, porque con bloques pequenos domina el coste fijo de cada
  llamada al sistema. El HDD alcanza ___ MiB/s en escritura y ___ en
  lectura, el SSD ___ y ___ (unas ___ veces mas) y el RAID 5 ___ y ___.
  El RAID 5 lee mas rapido que un SSD porque reparte la lectura entre
  3 discos; en escritura la paridad limita la mejora a (N-1) discos de
  datos. El HDD queda muy por debajo de su hoja por la conexion USB 2.0
  (~40 MB/s reales). Bloque optimo (menor que da el 95 % del maximo):
  ___ (HDD), ___ (SDD), ___ (RAID 5)."

7. FASE 7 - ESPECIFICACIONES DEL FABRICANTE (modelo de 10)
---------------------------------------------------------------------
En el ANFITRION (en la MV salen como QEMU HARDDISK):
  lsblk -o NAME,SIZE,MODEL,SERIAL,TRAN,ROTA
  sudo smartctl -i /dev/sdc            (SSD: modelo, "SATA 3.x 6.0 Gb/s")
  sudo smartctl -d sat -i /dev/sdX     (HDD por USB)
  lsusb ; lsusb -t                     (480M = USB 2.0, 5000M = USB 3)
  sudo apt install -y smartmontools    (si falta)

Valores teoricos:
  SSD HP S650 240 GB  SATA III  lectura 560 MB/s  escritura 460 MB/s
  HDD 1 TB externo    USB       la de su hoja (2,5": 100-140 MB/s)
  RAID 5 (3 x S650)             lectura <= 3 x 560 = 1680
                                escritura ~ (3-1) x 460 = 920

UNIDADES: el script mide MiB/s, el fabricante da MB/s.
  MB/s = MiB/s x 1,048576   (500 MiB/s = 524 MB/s)

Tabla de contraste:
  Dispositivo | Op. | Teorico MB/s | Medido MiB/s | Medido MB/s | %

Referencia P3: SSD 550 MB/s lectura (98 %), 520 escritura (por encima de
460: el fabricante da escritura sostenida conservadora + cache SLC).
HDD 36-42 MB/s.

Explicaciones:
  - SSD cerca del teorico: el limite es SATA III (~550-600 MB/s).
  - HDD muy por debajo: USB 2.0 (480 Mb/s brutos = 35-40 MB/s reales).
  - Perdidas: virtualizacion (QEMU), ext4, dd con 1 operacion en vuelo.

10. ERRORES TIPICOS Y ERRATAS
---------------------------------------------------------------------
Erratas del enunciado:
  systemclt                        -> systemctl
  echo -e "g\nw\n" | /dev/sdb      -> echo -e "g\nw\n" | sudo fdisk /dev/sdb
  count 1k = 1048560               -> 1048576
  200M y 100 GB a la vez           -> +100G
  monta /mnt/SDD, captura /mnt/SSD -> usa siempre /mnt/SDD
  contrastar SDD con hoja del HDD  -> cada disco con su hoja

Errores y arreglos:
  Device or resource busy (mdadm)  -> RAID viejo: mdadm --stop /dev/md127
  cannot open /dev/sdd1/: Not a directory -> sobra la / final
  umount: target is busy           -> cd ~
  mount: wrong fs type             -> falta mkfs.ext4
  drop_caches: Permission denied   -> sudo bash script.sh
  sed: orden s sin terminar        -> tecla muerta ^ (pulsa ^ + Espacio)
  mv: target ~examen/ no existe    -> es ~/examen/
  lsblk: columna desconocida       -> NAME,SIZE,SERIAL sin espacios
  Lista larga de tipos con ":"     -> q para salir
  Letras sdX distintas             -> identificar por SERIAL y tamano
